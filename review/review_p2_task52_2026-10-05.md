## 3. 发现

### P3-1 `build_source_graph` 的 `app_build` 兜底是**第二套实现**，与运行时侧不同 —— 「源图范围与运行时图对齐」这条承诺在兜底分叉时不成立

- 运行时侧（`cli/main.py:324`）：`bi.metadata_identity(meta_path).build or DEFAULT_APP_BUILD`，而 `cli/pipeline.py:40` 定义 `DEFAULT_APP_BUILD = "local"`。
- 源图侧（`graph/builder.py:266`）：`app_build = str(metadata.get("build") or "")`。
- **同一概念两处实现，兜底值不同**。探针实测：

  | metadata 输入 | 源图 `app_build` | 运行时侧 `app_build` |
  |---|---|---|
  | `{"build": "1026"}` | `"1026"` | `"1026"` ✅ 一致 |
  | 无 `build` 键 | `""` | `"local"` ❌ 分叉 |
  | `{"build": None}` / `{"build": ""}` | `""` | `"local"` ❌ 分叉 |

  而 `build_source_graph` 的 docstring 写的是「源图的范围**应与运行时图对齐**（diff 按 build 关联，设计 12.3）」——分叉时这句话不成立，后果是 diff 找不到同一 scope 的两面（全部落成「声明未到」或空）。
- **同一个问题在真机上已经显形（但方向相反）**：仓库真 metadata 的 `build` 是 `"local"`，而 Gate M2 的 `trace_run1/2.db` 的 `runs.app_build` 是**空串**（早于 Task 5.1 的写入修复）→ 用**默认值**建两面时 scope 不同（`('com.phaset0.logindemo','local')` vs `('com.phaset0.logindemo','')`）。提交声称的「真机端到端（**同 (app_id, build)** 两面）10 vs 3」只有在**显式传 `app_build=""`** 时才复现（探针 #5 实测：显式 `""` → 同 scope → 7 / 0；默认 → 不同 scope）。所以那组数字是对的，但它的前提没写出来。
- 建议（Task 5.3 接线前）：让源图的 build 兜底与运行时侧**共用同一个解析入口**（或 CLI 显式传 `app_build`，并把「两面必须同 scope」写成 `graph diff` 的前置检查——不同 scope 时 fail-loud 而不是安静地报满屏 NOT_OBSERVED）。这是本项目写进记忆的一条老教训（「两套实现必然漂移：同一概念只许一处实现」），此刻是最后一次便宜的收口机会。

### P3-2 `generated_at` 不做类型校验 —— 同一个函数里「坏输入不吞」只对 `screens` 生效

- `declared_screens` 对 `screens` 的校验很严（非 list / 非字符串 / 空串 → `ValueError`），但 `build_source_graph`（`graph/builder.py:264`）直接把 `metadata.get("generated_at")` 塞进 `ScreenNode.first_seen`，而 `ScreenNode.__post_init__` 只校验 `visit_count` 与 `screen_id`。
- 探针实测（真 `GraphStore` 落库）：

  | `generated_at` | 结果 |
  |---|---|
  | `123`（int） | **静默落库为 `'123'`**（SQLite TEXT 亲和性转换）——类型漂移，无人发现 |
  | `['a']` / `{'x': 1}` | 落库时 `ProgrammingError: Error binding parameter 7: type 'list' is not supported`——**在 upsert 处炸，离现场（build）很远** |
  | `None` | `NULL`（可接受） |
  | ISO 串 | 原样（正常） |

- 这与本任务自己的原则（「格式坏了要炸，不要静默产出」）矛盾：**同一个函数对两个字段用了两套标准**。建议 `generated_at` 也校验 `str | None`（几行），把错误留在 build 现场。

### P3-3 「**固化**体检」并未固化：仓库里没有任何「重复测试名」守护测试

- `aadb8b3` 的提交信息写「**固化体检**：全仓 `tests/**.py` 扫「def 名重复」，现零命中」。
- 实测：`tests/` 下**没有**任何测试在做这件事——`grep` 全仓 `import ast` / `from ast` / `import collections` / `FunctionDef` 在 `tests/`、`scripts/`、`conftest.py` 全部**零命中**。也就是说「固化」= **手工跑过一次**，不是「加了一条会自动失败的守护」。
- 为什么这条值得单独记：这是同类缺陷的**第三次**发生（`review_p2_task43` P3-3 的 56 行重复块 → `review_p2_task51` P3-1 的新增测试各定义两次 + 存量 3 个 `test_resolve_app_build_*`），根因每次都是「`cat >>` 追加被重复执行」。零命中的状态只在这一刻成立——没有守护，第四次会照样溜过去。
- 建议：新增 `tests/unit/test_repo_hygiene.py`（几行 ast 扫描：`rglob("*.py")` → 顶层 `FunctionDef` 名 `Counter` → 断言无重复）。它同时会把「def 数 vs `--collect-only` 数」这条对账手段变成**自动**的。

### P3-4 `declared_screens` 接受纯空白屏名

- 判据是 `not isinstance(item, str) or not item`——`"  "`（空白串）不是空串，于是被接受。探针：`{"screens": ["  "]}` → `['  ']`，会成为一个名叫两个空格的节点。
- 可达性低（扫描器不会产出空白屏名），故 P3。若要与「非空」的措辞严格一致，改成 `not item.strip()`。

## 4. 未验证 / 存疑

- **扫描文件数：我实测 109 个 `source_metadata.json`，提交称 165 个。** `out/` 是工作目录（每次 run / 每次 pytest 都会生成副本，本次探针期间 `out/` 下就有 1230 个带 `runs` 的 trace 库），数量随时点波动。**结论不受影响**（无论 109 还是 165，导航关键词都是零命中），但「165」这个具体数字在文档里会过期，建议改成「全仓扫描（含 `out/` 的工作副本）」这类不带数字的措辞，或注明扫描时点。
- **`screen_elements[].name` 的排除理由里「diff 全变 ADDED/NOT_OBSERVED」是夸大**：真机 10 个名字里 **8 个与 `screens` 相同**，只有 2 个不同（`SpikeSheet`↔`SpikeScreenRoot`、`SpikeTab`↔`SpikeTabScreen`）。用错源只会让**那 2 个**屏错（外加漏掉 2 个真屏），不是「全变」。**决定本身是对的**（且给了专测），但理由的量化说法不准——这类「用一个夸大的后果去支撑一个正确决定」的写法，将来会被拿去当反例。
- **只有 35/109 个 metadata 有 `screens` 键**（探针 #2 的键频次）——即**多数 metadata 走的是「缺键 → 空图」这条分支**。这不影响正确性（如实为空是设计），但意味着 Task 5.3 的 `--from-source` 在大多数现成 metadata 上会产出一张**空源图**，diff 的结果是「运行时独有 = 全部」→ 满屏 ADDED。Task 5.3 演示时要用**带 `screens` 的那份**（`repository/generated/local/source_metadata.json`，10 个屏）。
- **空源图落库后不留任何行** → `list_scopes()` 里不会出现该 `(app_id, build, 'source')`。因此 Task 5.3 的 diff **不能**用「scope 是否出现在 `list_scopes()`」来判断「有没有源图」——必须直接 `load_graph(..., SOURCE)`（空图返回空值，语义清晰）。当前无消费方，属给 5.3 的提醒。
- **`read_source_metadata` 里有一处多余的局部 `import json`**（`graph/builder.py:289`；模块顶部 `:61` 已 `import json`）。无功能影响，纯冗余——顺带一提，不是发现。

## 5. 值得肯定

- **「转移如实为空」是用实测把 plan 的字面要求坐实的，而不是照着 plan 抄**：先扫全仓 metadata 的关键词（零命中），再据此把源图定义成「节点 + 空转移」，并把这条**数据面边界**写进 plan 的 Task 5.3 段与模块 docstring。这是 E12 最容易被写坏的地方——换成「按屏名字母序连成一条链」就能交出一张"看起来更完整"的图，而那正是 E12 禁止的编造。
- **`screen_elements[].name` 的排除有真机证据**：不是"我觉得应该用 screens"，而是列出了真机里两处具体的不同名（`SpikeSheet`/`SpikeTab` vs `SpikeScreenRoot`/`SpikeTabScreen`），并指出后者位于 `generated/<build>/elements/` 下、是**元素组**不是屏。并且补了专测钉住这条排除——把「将来有人图省事改用后者」这条路堵上。

- **把上一轮的 P2-1 教训直接写进新代码**：空图也带对的 `source_of=SOURCE`，并有专测断言——新任务没有重复踩上一轮的坑。
