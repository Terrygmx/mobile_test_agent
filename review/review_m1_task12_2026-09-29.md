## 3. 问题清单

### R6-1（P1）省略 screen 的 override 在限定名/elements_of 路径被静默忽略

设计 5.3 的**规范示例**就是 override 不写 `screen`（依赖与 generated 合并时继承）。实测（generated LoginView.login_button + screenless override→signin_button）：

| 路径 | 结果 |
|---|---|
| `resolve("login_button")` 短名 | `['signin_button']` ✅ override 生效 |
| `resolve("LoginView.login_button")` 限定名 | `['login_button']` ❌ override 被丢 |
| `elements_of("LoginView")` | `['login_button']` ❌ override 被丢 |

根因：`_element(element_id, screen=...)` 的匹配过滤是 `s == screen`，screenless（None）永远不匹配；只有 screen=None 的短名路径才有"继承 generated screen"的合并逻辑。**同一 override 一条路径生效、另一条静默失效**，直接违反 5.3 "不能静默覆盖"的精神——Task 1.6 的 runner 混用短名/限定名时，这就是定位漂移的隐形来源。

**建议**：显式 screen 匹配时把 screenless override 纳入候选（`s in (None, screen)` 且存在 generated 同 screen 对应时继承），并补三条路径一致性测试。M3 generated 真正接入前修掉，成本最低。

### R6-2（P2）prepend/append 新增 accessibility_id 误报 `override_shadows_source`

实测：prepend 一个 generated 中不存在的新 id（`brand_new_fallback`）→ 误报 "shadows source 'login_button'"。**新增 ≠ 冲突**；5.3 的 warning 语义是"override 与 generated 的值冲突"。当前实现只要 override 的 accessibility_id 不在 generated 集合内就告警，M3 一开 prepend 场景 warning 会泛滥、淹没真冲突。建议：仅 replace 模式比较值冲突，或按"同一 generated 策略被改写"判定。

### R6-3（P2）metadata 枚举 typo 炸裸 KeyError

loader 对 metadata 是 `dict[str, Any]` 不校验；`risk: EXTREME` 这类 typo 在 resolve 时以 `KeyError: 'EXTREME'` 裸抛，脱离了 loader 精心维护的 `RepositoryLoaderError` 可读报错体系。建议把 risk/idempotency/data_class 枚举校验前移到 `_validate_element_semantics`（与 type/mode/origin 同层）。

### R6-4（P2）`includes` 加载但不消费

ScreenDef 按 5.4 加载了 `includes`，但 `elements_of` 不合并子组件元素，代码中也无延期注释。M1 不实现可以，但要在 docstring/TODO 记账（同 R5-3 的处理方式），否则 M1 末冻结盘点时会漏。

### P3（不阻塞）

- 语义 ID 含 `.` 无校验：`id: a.b` 的短名 resolve 会被误判为限定名（`a.b` → screen=a）。建议 loader 禁止 id 含 `.`（限定名语法保留字）。
- `from_dirs`（唯一磁盘入口）无测试覆盖，测试全走低层注入。
- `load_element_file/load_screen_file` 名为 file 实为 dir，命名误导。
- `_dir_entries` 只收 `*.yaml` 不收 `*.yml`。
- `_element` 中 `(not explicit_screens and len(ov_matches) > 1)` 分支在 loader 键控下不可达（同键去重），属防御性死代码，可删或留注释。
- overrides YAML 中 `origin: manual` 携带 `source_file/source_line`：M1 手写种子阶段填真实溯源行号有价值（且行号全对），但语义上 source 系字段是给 `origin: source` 的，建议 YAML 头注释加一句说明，避免 M3 时误读。
