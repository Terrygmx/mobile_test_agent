## 3. 独立探针复核（review 新增验证，非复述脚本）

### 3.1 底层 marker 残留（本任务最大风险点）— 排除 ✅

NavigationStack push 后，底层视图是否还留在 XCUITest 树里，直接决定 Task 1.6 的 `current_screen` 会不会拿到多个 marker 走 AMBIGUOUS。Spike 的 NavigationStack 场景只验证了"新页 marker 唯一"，没验证"旧页 marker 是否残留"。

对实测 page_source 逐文件 grep：

| page_source | `screen.HomeView` 出现次数 | 当前页 marker |
|---|---|---|
| page_source_Search.xml | **0** | `screen.SearchView` ×1, visible=true |
| page_source_Detail.xml | **0** | `screen.DetailView` ×1, visible=true |
| page_source_Profile.xml | **0** | `screen.ProfileView` ×1, visible=true |

**XCUITest 的 NavigationStack push 会把底层视图整个移出 accessibility 树**——每屏恰好 1 个 marker，`current_screen` 的 13.2 三分支在真实导航流下不会踩"多 marker"分支。这个实测结论值得记住（M2 Design Detail/Sheet 类覆盖式页面时需重新验证，Sheet 不走 NavigationStack）。

## 4. 问题清单

### R9-1 (P2) verify 脚本 Login 场景 skip 分支 fail-open

`verify_task15_markers.py:75`：no_reset 下若启动即见 home_page，Login 场景记 `{"skipped": "already logged in", "passed": True}`——**零证据算通过**，且被 verdict 汇总 `all(r.get("passed", ...))` 消费。若某次改动恰好弄坏 Login 屏 marker，而这个分支被走到，回归会被吞掉。

**建议**：App 的登录态是 `@State`（不持久化），`driver.terminate_app(BUNDLE_ID)` + relaunch 必然回到 Login 屏——skip 分支可以直接换成主动重启，让 Login 场景永远有证据；或至少让 skipped 不计入 passed 且 summary 显式标注。

### R9-2 (P2) UDID 硬编码，机器绑定

`verify_task15_markers.py:19`：`UDID = "AEBDAE77-7C5B-468B-A5A7-01D41EDAAD9E"` 写死。换模拟器/换机/CI 环境直接废。

**建议**：`os.environ.get("MTA_SIM_UDID", <当前值>)`，或启动时 `xcrun simctl list devices booted` 自动发现，找不到时给出可读报错（而非 Appium 连接超时栈）。

### R9-3 (P3) 断言用裸字符串匹配

`marker_unique` 是 `src.count(marker_id) == 1`，children 是 `cid in src`——子串匹配无属性定位、无单词边界。当前场景无实际冲突（marker id 之间无子串包含关系），作为证据级够用；但 **Task 1.6 的 Gate 脚本（verify_p1_m1.py）建议改用 ElementTree 解析**（name 属性精确匹配 + visible 属性过滤），毕竟 Gate 要对 5 条用例的通过与否做正式判定。

### R9-4 (P3) 固定 sleep 编排

全脚本靠 `time.sleep(1.5)` 等导航，慢模拟器上有 flaky 空间。Task 2.1 wait engine 落地后回头替换即可，现在不改。

### R9-5 (P3) ContentView 成 vestigial 壳

计划列了 Modify ContentView.swift，实际未改（也确实无需改）——偏差无害。但 ContentView 现在只是 `LoginView()` 的纯转发壳，仍编译进 target。建议要么删掉（连带 pbxproj 两行），要么在 Task 1.6 顺手处理，避免后续 review 反复纠结。
