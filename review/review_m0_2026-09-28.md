## 三、发现的问题

### R4-1【P1】测试 import 依赖"从项目根以 `python -m` 启动"这一隐含条件

**实测证据**：
- `make test`（内部 `python -m pytest tests -q`）→ 2 passed，exit 0 ✓
- **裸 `.venv/bin/pytest tests/unit -q` → `ModuleNotFoundError: No module named 'tracer'`，collection error**

**根因**（两层叠加）：
1. `python -m pytest` 会把 **cwd（项目根）** 插入 `sys.path`，所以 `from tracer.redactor import redact` 成功；console-script `pytest` **不做**这件事 → 失败。
2. `test_smoke.py` 第 6 行的 `sys.path.insert(0, parents[1])` 插的是 **tests/** 目录（`parents[1]` = tests/），不是项目根（应为 `parents[2]`）——这个 hack 本身是错的，只是恰好被 `python -m` 的 cwd 行为掩盖，形同虚设。

**为什么现在就要修**：M1/M2 的 tests/ 会扩展到 `test_schema.py`、`test_repository.py`、FakeDriver 集成测、24 项故障注入（plan Task 1.1~4.3），全部依赖同样的 import 方式；且设计 17.1/plan 执行注意事项要求这些测试"脱离设备单测"并作为回归底线——**如果 CI 或队友用标准方式 `pytest` 跑，第一个测试文件就挂**。M0 的 Gate 意义就是把这个底座打牢，此问题应在本里程碑内关闭而不是带入 M1。

**修复方向（三选一，推荐 ①）**：
1. 项目根加**空 `conftest.py`**——pytest 收集时会自动把 conftest 所在目录插入 `sys.path`，一行解决，所有后续测试文件不用再写 sys.path hack；
2. `pytest.ini` 加 `pythonpath = .`（pytest ≥7 原生支持，当前 9.1.1 满足）；
3. 删掉根级 `__init__.py`（P0 遗留，包身份对单测无用）+ 删测试里的 sys.path hack。
无论选哪个：**删掉 test_smoke.py 里指错目录的 `sys.path.insert`**，避免后人复制这个错误模式到 20+ 个测试文件里。

### R4-2【P2】Makefile 注释错位

`# review P2-3：删除死代码…` 这条注释描述的是 `scan` 目标的历史改动，但现在悬在 `test:` 目标上方，语义误导。挪到 `scan:` 上方或删除。

### R4-3【P2】`-q` 重复配置

`pytest.ini` 的 `addopts = -q` 与 Makefile test 目标的 `tests -q` 重复。无害，但后续 CI 若想改输出级别会改两处。建议 Makefile 去掉 `-q`，以 pytest.ini 为单一大本营。
