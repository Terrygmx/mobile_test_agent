## 3. 发现

### P2-1 storyboard 行号恒 0（排障锚点失效一半）
- 位置：`source/storyboard.py:118` `line = getattr(el, "_line", 0) or 0`
- 探针实锤：标准 `ET.parse` 产出的 Element **没有 `_line` 属性**（自定义 TreeBuilder 才有）→ 所有元素 line=0。commit 声称「文件名+行号是唯一排障锚点」，实际行号永远无效；`id=f"UNKNOWN:{file}:{line}"` 退化成 `UNKNOWN:x.storyboard:0`，同文件多个 unknown 元素不可区分。
- 测试零覆盖（test_storyboard.py 无任何 line 断言）。
- 修复建议：包一层 expat——`parser = ET.XMLParser(); tree = ET.parse(p, parser)` 后用 `parser.parser.CurrentLineNumber` 不可行（时机问题），推荐自定义 TreeBuilder 在 `start()` 里记行号（配合 `xml.parsers.expat` 的 `CurrentLineNumber`），或换 `lxml`。并补测试断言 line>0。

### P2-2 一致性 Gate 前缀覆盖吞掉真实漂移（REMOVED 漏报）
- 位置：`source/consistency.py:109` `_covered_by_prefix`
- 探针实锤：overrides 同时登记 `cell_alpha`（插值实例，预期豁免）与 `cell_removed`（App 侧已删的真实漂移），generated 只有 `cell_` 前缀 → `cell_removed` 满足 startswith("cell_") 被**一并豁免**，REMOVED 空，Gate 对该漂移静默。插值 cell 越多（前缀越短/越通用），盲区越大。
- 修复建议：不直接丢弃，前缀覆盖的 pair 归入新桶（如 `prefix_matched`），报告单独列出「以下 REMOVED 被插值前缀覆盖，请人工确认」；`ok` 语义可维持不变，但漂移必须可见。这符合 12.2「人工确认」的精神——现在是自动豁免，不是人工确认。

### P2-3 generated 运行时零消费：`mta run` 无 `--generated` 参数（R10-5.2 未闭环）
- 位置：`cli/main.py` `_load_repository` vs run 子命令参数表
- 实锤：`lint` 有 `--generated`；**`run` 没有** → `_load_repository` 里 `getattr(args, "generated", None)` 对 run 恒 None，运行时 Repository 仍是「overrides 兼职 generated」的旧 workaround。generated 目录当前只有 `mta repo generate` 导出与 round-trip 测试消费。
- 这是本项目「实现存在但零消费」平行实现模式的**第 6 次**（R11-4/R13-2/R14-2/R15-2/R16-4 之后）。commit 自认 TODO(M3, R10-5.2)，可以收口 3.1，但必须显式记账（p1_schema_review.md），防止 Task 3.3 的 Gate 用「手写基线 vs 合并」验证时误以为运行时已接 generated。

### P3-4 local 生成必 dirty：generated_at/git_commit 每次变
- 本次 review 跑一遍 `repo generate` 即留下 `M repository/generated/local/source_metadata.json`（git_commit 963f307→d9df9d5、时间戳）。12.4 定位是 CI 构建产物；local 的 `generated/local/` 若入库则每次跑都脏。建议拍板：local build 产物 `.gitignore`，或接受噪音并在 CONTRIBUTING 写明。

### P3-5 `--check` 硬编码相对路径
- `cmd_repo` 里 `check(meta, "repository/overrides")` 依赖 cwd；`--out/--build` 都参数化了，overrides 根也该参数化（默认现值即可）。

### P3-6 container struct 名生成的 screen 条目 marker 是猜的
- 实锤：`generated/local/screens/SpikeTabScreen.yaml` marker=`screen.SpikeTabScreen`，但 App 实际声明是 `.mtaScreen("SpikeTab")`（SpikeScreen.swift:22）→ 该 marker 在真机永远匹配不到。无害（current_screen 0 匹配→UNKNOWN，且正确的 SpikeTab 也已登记），但污染 repo，且将来 lint 若校验 marker 可达性会误报。
- 建议：screen 条目只从顶层 `screens`（mtaScreen 声明）生成；container 名仅用于元素归属——export.py 注释自己也说「两者都要可解析」，但 struct 名并非 marker 名，导出为 screen 定义属于猜值（12.2 同源纪律）。

### P3-7 杂项
- `export.py:104` `_element_metadata(el)` 参数未用（死参数）。
- `storyboard.py` `_map_containers` 的 `tag.endswith("ViewController")` 匹配不到 `tableViewController`/`collectionViewController`（小写 v 开头）等 scene，其子元素 container 落 None→UNKNOWN（有兜底，不致错，归属变粗）。
- `SwiftUIVisitor.location(of:)` 每个 modifier 调用都新建 `SourceLocationConverter`，大文件 O(n²) 隐患——正确性无碍，P3 性能项。

## 4. 值得肯定

- **fail-loud 纪律**：scanner 缺失/非零/空输出/坏 JSON 全部 ScanError，不把「没扫成」伪装成「零元素」——这正是本项目反复强调的诚实语义。
- **12.2「不猜值」贯彻最彻底的一轮**：常量表歧义剔除、插值只出静态前缀且 accessibility_id 恒 nil、export 只导 literal/constant（dynamic/unknown 导出即造假——想明白了才写得出这条）。
- **白名单单一真值源**：export 直接 `from repository.loader import ELEMENT_TYPES`，杜绝两处白名单漂移（且测试实锤过 list/toggle）。
- **IB 直接子查询**：`_attr_value` 只查直接子 userDefinedRuntimeAttributes，防祖先容器误吸（3→13 假元素，有实测记录）。
- **`_scan_binary` 函数内构造**：模块级 tuple import 求值导致 monkeypatch 失效的坑已主动避开并写明原因。
- **SwiftSyntax 新版 API 的探针方法**：SequenceExpr 折叠、visit 顺序、行号取参数位置，全部有「探针实锤」记录，不是凭印象。
