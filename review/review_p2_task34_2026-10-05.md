## 3. 发现

### P2-1 revalidate 的「Guard+执行」偏离：三处陈述互相矛盾，且证据是无校验的自报字符串
- **plan step 1 原文**（`docs/phase2-plan.md` Task 3.4）仍写着「revalidate 对 DEGRADED 走一次 **Guard+执行**并按结果转状态」——本次提交未触碰 plan 文件，该句原样保留。
- **commit message** 声称「revalidate 的『Guard+执行』自动化登记偏离：…**plan 已注明**」——plan 里没有这个注明（前置②只写了护栏与错误信息）。宣称与磁盘不符，属本项目记账纪律（「宣称≠存在」）的现行犯。
- **代码侧是诚实的**（verifier docstring：「本函数不自己跑验证：验证证据由调用方（跑了一次真机验证的人/命令）提供，fingerprint 就是那次观测」）——但 `--fingerprint` 的内容**零校验**（任意非空串、甚至空串都能过 argparse），DEGRADED→VERIFIED 的唯一出口凭一次自报声明即可完成。revalidate 是「显式重验证」的唯一路径，它的证据强度就是 VERIFIED 档位的含金量。
- 建议三件：①plan step 1 改写为登记后的语义（「CLI 出口为人工自报证据留痕；Guard+执行的自动化验证留待 M4+ 的设备会话路径」——一句话）；②commit 侧更正说明（下一条 commit 的 message 里点一句）；③最小证据强化：`--fingerprint` 非空校验 + CLI 输出明示「证据为操作者自报（operator 留痕）」，将来可选 `--evidence-run-id` 挂真实 run。

### P3-1 `repo.resolve(f"{screen}.{target}")` 对 container/marker 名分裂的 App 会静默收窄 E4
- resolve 走容器前缀引用；P1 P3-6 的教训是「container struct 名 ≠ marker 名」（SpikeTabScreen vs SpikeTab）。元素若按 marker 归属登记，`{screen_id}.{target_id}` 解析失败 → `ELEMENT_UNRESOLVED` → 一律 NOT_ELIGIBLE——fail-closed 方向安全，但会把「本该可自动验证」的候选静默挡在门外。建议 resolve 失败时回退按裸 `target_id` 再试一次（或报告里区分「元素不存在」与「screen 归属不一致」两类原因）。

### P3-2 `verify` 的资格三态被压成 bool
- 非 CANDIDATE 的 `eligible=None`（不适用）与 False（不合格）在 `auto_verify_eligible=bool(eligible)` 处合并。当前 evaluate 的 DEGRADED/VERIFIED 分支不消费资格，无实害；但将来若 evaluate 消费（如 revalidate 资格），None 与 False 不可区分。建议签名直接收 `bool | None` 传递。

### P3-3 杂项
- `verify` 的报告行把 `repo_error`（含异常文本）打给用户——信息量好，但异常文本可能含路径/内部细节，长期看值得归类为稳定文案。
- `ELEMENT_UNRESOLVED:` 后的手工换行拼接（f-string 反斜杠续行）——格式无害，风格与 4.1 review P3-4 的「多空格行」同族，编辑器层面收口。

## 4. 值得肯定

- **E4 单点的接线是「真的」**：资格不是 CLI 里的一个布尔常量，而是从 Repository 解析出元素、经 `eligible_for_auto_verification` 算出来的——Gate S5 用真 CLI 断言（非幂等 10/10 不升级），我的探针用真 overrides 独立复现（MEDIUM 与 LOW 的 10/10 命运分叉）。review_p2_task31 担心的「E4 零调用面」问题就此关闭。
- **CLI 零判据复制**：五个子命令全部是 experience 包纯函数的编排与 IO——「CLI 不复制任何判据」的注释与 import 面完全一致，Verifier 的单测继续是唯一权威。
- **护栏出口的「下一步」设计**：revalidate 被拒时按当前状态给出三条不同路径（CANDIDATE→verify / REJECTED→重新 ACCEPT / VERIFIED→无需）——把状态机红线翻译成用户可执行的下一步，而不是一句裸报错。
- **Gate M3 的离线性**：offline=true、0.2s、矩阵 #12 用 200 次双线程并发写把 E9 又钉了一遍——判据可重复执行，不是一次性演示。
