## 3. 发现

### P2-1 运行时变量解析缺失 + lint 占位符检查可绕过——真机 Gate 的用例值实际是坏字面量（探针实锤）
- 位置：`runner/runner.py`（无任何 `${VAR}` 解析）、`cli/pipeline.py:624`（`ctx.value=step.value` 原样透传）、`testcase/lint.py:28`（`SECRET_REF = \$\{([A-Za-z_]\w*)\}`）、`phase0/verify_p1_m4.py:205`
- 实锤三连：①committed 的 drift_001.yaml 里是 `value: ${{TEST_USERNAME}}`（脚本把普通字符串当 f-string 转义了双括号）；②lint 的正则对 `${{…}}` **不匹配** → 带病用例照常进 run（实测 findall 返回空）；③运行时把字面量 `${{TEST_USERNAME}}` 敲进了输入框——demo App「任意非空即成功」让整个 Gate 全绿属**侥幸**。设计 §14.4（750 行）明文「变量解析在 Runner 层完成」，至今无人实现；lint 是唯一防线且有绕过形态。
- 后果：H9 的「密钥只经 SecretProvider 获取」在运行时层面不成立（既没解析、真密钥也从没进过 App）；对真实 App（严格校验凭据）这类用例会 FAIL 而非暴露原因。
- 修复建议：①脚本两行改单括号（立刻）；②lint 对 `${{`/`${` 无合法闭合的形态报 malformed ERROR；③Runner/pipeline 分派前经 SecretProvider 解析（设计明文，sensitive 值的 Redactor 兜底已有——补一条「解析后的值不落 trace」断言）。

### P2-2 `--allow-production` 死旗标 + 真机 Guard 恒 SANDBOX + runs.env_kind 从不落库
- 位置：`cli/main.py:76`（argparse 定义）vs 真机分支 `Guard(EnvKind.SANDBOX)` 硬编码；全仓 `args.allow_production` 零消费者；runs.env_kind 列恒 NULL。
- 后果：矩阵 #22（production + CRITICAL → SECURITY_BLOCKED）在**生产入口不可达**——该语义只在测试里通过 guard 注入存在。R18-4 先例（--no-llm「参数存在≠功能存在」必须 help 如实标注）：这个 flag 的 help 写着「允许 production 环境（10.1 总闸）」，是谎言。
- 修复建议：cmd_run 把 flag 接进 Guard（`EnvKind.PRODUCTION if ... else SANDBOX`；env 自动探测 P1 无现实来源可后续做），allow_production 透传，env_kind 落 runs 审计列；或摘除 flag。

### P3-1 #13 的「不触发 LLM」断言是间接证据
- `test_matrix_13_24.py:80-83` 用 `recovery_reviews == 0` 证明「未触发 LLM」——但 LLM 被调用且返回垃圾（无候选→无 review）时该断言同样通过。设计原文是「**不触发 LLM**」。建议保留 FakeLLM 引用，断言 `llm.calls == []`（#10 的计数断言先例就在同文件族里）。

### P3-2 死导入 + #10 的两段 no-op replace
- `test_matrix_01_12.py` / `test_matrix_13_24.py` 的 `import pytest` 未使用；`fi_support.py` 的 `LLMBudget` 未使用；`test_matrix_01_12.py:226-228` 的 `case_b` 构造含两段 no-op `.replace()`（`"fi_10b"→"fi_10b"`、`"fi_{case_id}"→"fi_10b"` 对已格式化字符串），读起来像在做重要的事。

### P3-3 `_run_status` 把 ENVIRONMENT_FAILURE 并进 "INFRA_FAILURE"
- `cli/pipeline.py:911`：用例级 8.1 区分 INFRA_FAILURE/ENVIRONMENT_FAILURE，run 级合二为一——#20 的 run 落 status=INFRA_FAILURE（exit 2 正确）。RECOVERED 终态修复的邻居问题，pre-existing；M5 的 50 轮报表会按 runs.status 出比例，语义先拍板（合并有理就记账）。

### P3-4 run_all 真正未捕获异常时 runs 行停留 RUNNING
- SuiteAborted 已被 `run_all` 捕获并正确 end_run；但 RecoveyEngine/管线自身的 bug 级异常会穿透——runs 行停留 RUNNING、无 exit_code。TraceStore 没有 Recorder 那条「启动时清理 RUNNING 残留」。触发条件=有 bug（低概率），但「不写假终态」纪律同样要求「不留无终态」。
