## 3. 问题清单

### R5-1（P1）设计 §6 官方示例无法通过 0.1 schema 校验

实测：把设计文档 §6 的 YAML 示例转 dict 后调 `parse_testcase_dict` → **ValidationError（11 条）**。三处契约脱节：

| # | 设计文档写法 | 实现写法 | 后果 |
|---|---|---|---|
| a | `wait_for` 内有 `polling_interval: 0.3`（§6 示例第 262 行） | WaitSpec 无此字段，extra="forbid" 直接拒 | 带轮询间隔的合法用例被拒 |
| b | assertion 体用 `type: exists`（§6 示例第 265 行） | AssertionSpec 字段名是 `condition` | 设计示例的 assertion 缺 `condition` 且 `type` 成未知键，双重失败 |
| c | wait 条件 ∈ `exists/not_exists/visible/enabled/disabled/text_equals/text_contains/active`（§6.2 表） | WaitSpec 缺 `text_equals`、`text_contains` | 文本等待类用例无法表达 |

**影响**：schema 是 M1 后续所有任务（Repository 解析、lint、Executor 消费）的契约源头。现在不拍板，Task 1.2 的测试用例 YAML、Task 1.4 的 lint 规则各自按不同假设写，到 M1 Gate 冻结时返工面更大。

**建议**（二选一，工作量都不大）：
- **改 schema**（若 polling_interval 属于用例可调）：WaitSpec 补 `polling_interval: float = 0.3` + 补两个文本条件；AssertionSpec 加 `type` 别名或统一改用 `condition` 并回写文档；
- **改文档**（若轮询节奏归 Executor Policy，更符合 H7 精神）：§6 示例删 `polling_interval`、assertion 键改 `condition`、§6.2 wait 行删文本条件，并在 schema.py docstring 注明「文本等待用 assertion 表达」。

倾向后者：wait 的文本条件与 assertion 职责重叠，砍掉更干净；但这是设计决策，需要你拍板。

### R5-2（P2）双 TestCase 并存，文件级 loader 可绕过全部严格校验

`testcase/loader.py` 现在有两个世界：旧 `TestCase/Step`（松散、无 forbid、无版本检查）和新 `load_testcase_from_dict`。P0 链路（`run_phase0_demo.py`、`verify_stage5.py`、`verify_stage9_f5.py`）仍走旧模型——兼容本身没问题；但 `load_testcase(path)` **不检查 schema_version**：将来有人写一份带 `schema_version: "0.1"` 的 YAML 用 `load_testcase` 加载，会拿到旧松散模型，strict 校验全部静默旁路。

**建议**：`load_testcase` 开头检测 `data.get("schema_version")` 存在即转发 `parse_testcase_dict`（一行改动 + 一个测试）。可带入 Task 1.2。

### R5-3（P2）precondition/cleanup 仍是裸 dict，reset 枚举未校验

设计 §6.3 是 `precondition: EnvSpec`（reset ∈ RESET_STATE/RELAUNCH/TERMINATE/LOGOUT/REINSTALL/SNAPSHOT）+ `cleanup: CleanupSpec`（含 `failure_policy`）。实现为 `dict`，`reset: RESET_STATEE` 这类 typo 会静默通过，直到运行期才炸。若属有意延期到 Task 2.x（reset 策略落地时再定型），建议在 schema.py 加注释记账，避免 M1 末冻结时遗漏。

### R5-4（P2）union 解析失败的报错可读性差

`steps: list[ActionStep | WaitStep | AssertionStep]` 依赖 pydantic smart-union；`{"wait_for": {...}}` 会先对 ActionStep 试一遍并产出「Field required (action) / extra_forbidden (wait_for)」级别的噪音错误（本次实测 11 条）。三个形态键互斥，可在 TestCase 加 before-validator 按首个 key 显式分发，报错直指真正原因。非阻塞，建议随 0.2 一起做。

### R5-5（P3·卫生）`testcase/loader.py` docstring 陈旧

仍写着「Stage 5。ponytail: pydantic 只建用到的字段」，与本文件现状（P1-01 入口 + 旧模型兼容层）不符，顺手更新即可。
