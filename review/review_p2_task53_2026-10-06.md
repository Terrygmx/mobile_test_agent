## 3. 发现

### P2-1 「当前面为空」不判 UNKNOWN —— 忘了建运行时图会得到 `exit 1` + 满屏 `NOT_OBSERVED`

- `diff_graphs`（`graph/diff.py:201-209`）只对**参照面**做保守处理：`base is None or new is None` → 全 UNKNOWN；`not base.nodes and not base.transitions` → 全 UNKNOWN。**对 `new` 为空图没有任何检查** → 走正常分支，参照面的每个条目都落进 `NOT_OBSERVED` 分支（`:219-226`），`changed=True`，CLI 退出码 1。
- 而「空图不留行」使**「没构建过」与「构建了但为空」在库里不可区分**——这正是模块 docstring 口径 2 自己承认的前提（原文：「库里『没构建过』与『构建了但为空』不可区分（空图不留行）」）。口径 2 只把这个不可区分性用在参照面上，当前面则默认「为空 = 确实什么都没观测到」。
- 探针（**首次使用路径**：只建源图、从不建运行时图）：

  | 操作 | 结果 |
  |---|---|
  | `mta graph build --from-source meta.json`（2 个屏） | 落 1 个 scope：`(app, '1026', 'source')` |
  | `mta graph diff --build 1026` | **exit 1**，`NOT_OBSERVED screen LoginView` + `NOT_OBSERVED screen SearchView`，`UNKNOWN=0` |

  纯函数对照更清楚：`diff_graphs(base=2 节点, new=空图)` → `NOT_OBSERVED=2, changed=True`；`diff_graphs(base, new=None)` → `UNKNOWN=2, changed=False`。**同一件事（运行时面没有数据）因为传 `空图` 还是 `None` 得到相反结论**，而 CLI 走的是前者。
- **为什么现在报**：CLI 的 scope 对齐守卫（`cli/main.py:1376-1394`，上一轮 P3-1 的接线前置）只在「那一面**在别的 build 上有图**」时才触发；首次使用时库里根本没有运行时行 → 守卫落空 → 用户拿到一个**自信的 exit 1**。CI 会把 exit 1 读成「图变了」，人会读成「用例没走到这些屏」，而真相是「你还没建运行时图」。这恰恰是守卫想防的「scope 没对齐伪装成声明缺失」，只是方向反了。
- 修法（建议 Task 5.4/5.5 前定）：把「当前面为空」与「参照面为空」同等保守（都 UNKNOWN + 写明原因），或让 CLI 在 diff 时对「那一面在库里完全没有行」给出 `GRAPH WARN`（build 时已有 `GRAPH WARN: 运行时图为空`，diff 时没有）。**权衡**：真·「观测到 0 个屏」也会变成 UNKNOWN，失去 NOT_OBSERVED 信号——但那个信号在 `graph build` 时已经用 WARN 给过一次了。

### P3-1 `_trans_of` 只按 `(from_screen, trigger)` 索引 —— 同键多目标时**静默丢弃**一条

- `graph/diff.py:158-163`：`out[(t.from_screen, t.trigger)] = t`。而 schema 的唯一键是 `(app_id, app_build, from_screen, to_screen, trigger, source_of)`（`001_graph_schema.sql:45`）——**允许**同一 `(from, trigger)` 有两个不同 `to` 的转移共存。两者不一致：diff 的 CHANGED 模型假设「一个触发条件一个目标」，但这个假设既没被强制，也没被声明。
- 探针：参照面同时含 `(A, tap:go) → B` 与 `(A, tap:go) → C`

  | 比较 | 结果 |
  |---|---|
  | `diff(base, 空运行时)` | 只报 1 条 `NOT_OBSERVED A->C` —— **`A->B` 彻底消失** |
  | `diff(base, (A, Z, tap:go))` | `CHANGED A->Z`，`was_to='C'` —— 原目标只取到 C |

  字典按插入序覆盖，而 `graph.transitions` 是按 `(from,to,trigger)` 排序的 → 保留的是**字典序最大**的那个 `to`，没有任何提示。
- 可达性：运行时图里同一 `(from, trigger)` 指向不同屏 = 同一个动作在不同 run 里去了不同地方（应用不稳定或真有分支）。此时**真的删掉一条转移也不会被 diff 发现**。
- 修法：遇到同 `(from, trigger)` 多目标时 **fail-loud**（假设被违反就说出来），或把索引改成「键 → 目标列表」显式支持多目标。无论哪种，别静默丢。

### P3-2 `graph_diffs` 不持久化「比的是哪两面」

- `GraphStore.record_diff`（`graph/storage.py:104`）落的是 `(app_id, base_build, build)` + 条目列，**没有 `base_source_of` / `source_of`**；`load_diff`（`:128`）返回的字段实测为 `['created_at','detail','from_screen','kind','screen_id','to_screen','trigger']`。
- 后果：**源图 vs 运行时**（`base_build == build`，两面来源不同）与 **build-to-build**（两面来源相同、build 不同）在库里长得很像，回读时无法判断这次比较是哪种；而 CLI 打印时是知道的（`base=source → new=runtime`）——信息在**打印时存在、落库时丢失**。
- `graph_diffs` 是 Task 5.1 冻结的三表之一，当时还没有这个需求（plan 要求三表同批冻结），所以这是**需求后到**而非疏忽。修法：加一列（或两列）`base_source_of`/`source_of` 走 graph 自己的迁移链（002），或至少写进 `detail_json`。
- 注意：`record_diff` 的替换范围是 `(app_id, base_build, build)`——源图 vs 运行时在 build X 下与「X→X 的 build-to-build」会撞同一个键。当前后者是退化用法，暂无实际冲突，但补上来源列后建议把来源也纳入替换键。

### P3-3 `test_graph_diff.py:195` 的死条件

- `diff = diff_graphs(base, None if False else new)   # 两面都在 → 走正常分支`——`None if False else new` 恒等于 `new`，是编辑残留（大概原本想构造 `None` 分支）。不影响断言（该测试的意图由后两行表达），但会让人读成「这里有个条件分支」。

## 5. 值得肯定

- **`REMOVED` 默认不可达是从设计字面推出来的，而且没有为了让「五类都跑得起来」而编数据**：设计要求「Source 明确标注 **且** Runtime 多次确认不存在」，后者需要**负证据**，而运行时图只记「到达了什么」（Task 5.1 的口径）——于是把负证据做成**显式入参 + 阈值常量**，明说「当前无生产者」，并在真机演示里如实呈现 `REMOVED=0`。真机 e2e 的 `ADDED=2` 也来自「源图无转移」这个已登记的边界，而不是造出来的。
- **`UNKNOWN` 的口径顺带堵住了一个静默误读**：多数现成 metadata 没有 `screens` → 源图本就为空 → 若照常判 `ADDED`，运行时的每个屏都会被算成「未声明」。把「参照面为空」判成 UNKNOWN 并写明原因，是在**保护一个还没人踩到的坑**。
- **跨范围 fail-loud 与 CLI 的 scope 守卫**：上一轮 P3-1 的接线前置被完整兑现——纯函数层 `ValueError`（app_id / app_build），CLI 层 exit 3 并**点名另一个 build**（实测消息 `base(source) 面在 build='1025' 上没有图，但同一 app 在 ['1026'] 上有`）。把「配置问题」与「数据缺失」分开，是这一层最该做的事。
- **`COALESCE(r.app_build,'')=?` 是冒烟里自己抓到的真 bug**：`--build ""` 本来会**静默得到空图**（NULL 不匹配 `''`），这种「静默空结果」最难发现。作者不但修了，还在注释里写清「scope 的 `''` 是归一化后的形式，库里是 NULL」。
- **守护测试自带防空转断言**（`test_hygiene_scan_actually_covers_the_repo`）：扫到文件数有下界 + `conftest.py`/`tests/` 必须覆盖 + `out/` 必须被排除。「零命中」的两种成因（真干净 / 根本没扫到）被区分开了——这是守护测试最容易被忽略的一半。
- **空图必须说出来**：运行时图为空 → `GRAPH WARN: …（既没有成功的 wait_for screen:X，也没有恢复期屏识别）`；源图为空 → `GRAPH WARN: …没有声明任何屏；此时 diff 会判 UNKNOWN`。把「如实为空」（设计允许）与「静默为空」（会让人误读）分开。
- **`record_diff` 沿用图的「按范围整体替换 + 单事务」语义**：重跑 `graph diff --save` 幂等（探针 #10），读者看不到半新半旧的差异列表——与 `upsert_graph` 同一套纪律。
- **退出码语义明确**：UNKNOWN 是「没判定」不是「有变化」→ exit 0；只有真实差异才 exit 1（CI 可用）。这条被写进注释、被测试覆盖，也被探针独立复现。
