## 3. 发现

### P3-1 RUN_MEMO 命中路径不消费 memo 策略（骨架可行，但测试注释言过其实）
- 位置：`agent/recovery.py` RUN_MEMO 块 + `tests/unit/test_recovery_policy.py:195-217`
- 实锤：memo 命中后引擎执行 `ctx.refind()`——它闭包捕获的是**原始 strategies**；`memo.save(..., {"type": "accessibility_id", "value": "go_profile_v2"})` 存进来的恢复策略从未被用来构造新定位。测试注释写「memo：按恢复策略重找命中」，实际 stub 的 refind 第二次调用恒成功，与 memo 内容无关——真实漂移场景下按原 strategies 重找会再次失败，9.4 目前是「查得到但用不上」的空壳。
- 定性：plan 本来就只要「RUN_MEMO 骨架」，不算违规；但 4.2 接 LLM 校验链后 memo 的 save 时机与**策略消费**必须闭环，否则复用语义名存实亡。建议进 4.2 验收清单。

### P3-2 `recovery.on_wait_timeout` 是端到端死旋钮
- 位置：`agent/policy.py:87`（决策表可放行）vs `cli/pipeline.py`（wait/assertion 步骤不进恢复管线）
- 实锤：决策表测试 `test_wait_timeout_admitted_when_config_enabled` 用 PRE phase 手工构造可过；但管线里 WAIT_TIMEOUT 只从 WaitEngine 产生，wait 步骤走 `_record_aux_step` 分支，**永远不会调 recovery**——`on_wait_timeout=True` 打开也没有任何代码路径能兑现。
- 定性：9.2 的「默认不进入」留了配置口子，P1 不实现可接受；建议要么在 mta.yaml 注释/文档注明「4.2 前无效」，要么 4.2 给 wait 步骤接恢复管线，别让配置项假装能工作。

### P3-3 矩阵 #15 顺延未点名记账
- 实锤：`p1_schema_review.md` 顺延 4.2 清单列了 reconcile 适配/LLM 校验链/review CLI/budget，但矩阵 #15（断言目标 ID 漂移 → 步骤 RECOVERED kind=assertion_target，exit 5）没有点名。该行的恢复需要 LLM 候选 + **断言步骤接入恢复管线**（现 assert 分支与 ActionStep 一样不进 recovery），是 4.2/4.3 之间容易被漏的活——4.3 要 24/24 全过，现在就该挂账。

### P3-4 测试精度两处
- `test_engine_experience_store_consulted_after_reconcile_before_llm`：`repo=None` 时 LOCAL_RECONCILE 整段跳过，stages 断言 `[settle, experience, llm]` 只证明了「experience 在 settle 后、llm 前」，**「reconciliation 之后」这个位置约束并未被该测试证明**（测试名声称了它）。补一个带 fake repo 的用例才闭环。
- postcondition 双查：StepRunner 成功路径查一次（runner.py:259-271），不满足进引擎后 `postcondition_check` **再查一次**——两次结果不一致（时间窗口内页面恰好就绪）时以第二次为准。这其实给了二次机会，行为无害甚至有益，但两次查询的语义差（第一次失败已落 post_detail）值得在 4.2 校验链设计时显式定档。

### P3-5 杂项
- `agent/recovery.py:1` 模块 docstring 仍是 P0 时代的「Stage 8，设计文档 4.8.3」——模块现在主体是 P1 引擎，开头却只介绍 P0 函数，新人第一眼会误读。改成两段式说明（P0 遗留 + P1 引擎）。
- `cli/pipeline.py:419` `checker = getattr(...)             if runner is not None else None`——13 个多余空格的条件表达式（语法合法，repr 字节已验证是真实文件内容）。顺手格式化。
- `runner/suite.py` `run_suite` 循环体内 `len(list(testcases))`——若调用方传 generator 会被 list() 半路消费（现调用方都传 list，无实害）；防御性收口或注释一句。
