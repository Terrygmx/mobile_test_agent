## 4. 问题清单

### R10-1 (P1) pbxproj 改动未提交，`checkpoint-p1-m1` tag 无法重建 App

`5fb076d` 删除了 `ContentView.swift`，但对应的 pbxproj 修改（移除 fileRef/buildFile/sources 三处引用）**至今躺在工作区未提交**（review 时 `git status` 可见 `M ios_demo/LoginDemo.xcodeproj/project.pbxproj`）。后果：`checkpoint-p1-m1`（以及 `checkpoint-p1-task1.5-r9`）两个 tag 上，pbxproj 引用不存在的文件——干净 checkout / CI 全新构建 `xcodebuild` 必失败（missing file reference）。本机能跑只是因为模拟器里已装了二进制。

**修法**：提交该 pbxproj 改动；若要求 tag 精确，删除并重打 `checkpoint-p1-m1`（本地 tag 未推送可安全重打；`origin/P1-0929` 已推到 5fb076d，注意同步）。

### R10-2 (P2) `postcondition` / `cleanup` 声明了但 runner 零消费——静默丢弃

`logout_001` 写了 `postcondition`（screen:LoginView active），但 runner 全文无 postcondition/cleanup 处理（grep 实证），lint 也不告警。5/5 PASS 是因为 Gate 的终态 marker 断言**恰好**覆盖了同一验证点——但这条 YAML 里的声明实际是死配置。M2 Gate 硬性要求「cleanup 失败终止套件」，cleanup 引擎 + postcondition 失败语义是 M2 第一批的事。

**建议**：短期让 lint 对 runner 未消费的声明报 error（fail-loud，防止 YAML 作者以为生效）；M2 实现时再翻正。

### R10-3 (P2) schema_review 文档自相矛盾：EnvSpec 到底进没进 0.2

`docs/p1_schema_review.md` 第 5 节：「**0.2 升版时一并定型 EnvSpec**（枚举：RESET_STATE/RELAUNCH/TERMINATE/...）」；结论节：「EnvSpec 定型**顺延**至 M1 末冻结盘点」。实际 schema.py 0.2 只有版本号变更，无 EnvSpec——第 5 节的承诺没兑现，结论节又把"0.2"和"M1 末冻结"当成了两个时间点（按计划 0.2 就是 M1 冻结版）。R5-3 由此仍然开放：`precondition.reset` 仍是裸 dict，`RESET_STATEE` typo 依旧静默通过到运行期（reset_state 的 matrix 会在运行期抛错，fail-loud 兜底了，但 lint 阶段就该拦）。

**建议**：0.2 已 tag 不宜动，把第 5 节改写为「0.2 未含 EnvSpec，顺延 0.3/M2 开头」消除矛盾，并把 R5-3 的记账位置写死；M2 开头升 0.3 时一并定型。

### R10-4 (P2) `_do_wait_for` 忽略 `condition` 字段

WaitSpec.condition 枚举有 active/exists/text_contains/...，最小实现只轮询 find、从不读 `w.condition`——YAML 若写 `condition: text_contains` 会**静默按"元素存在"处理**。当前 5 条用例只用 `active` 所以没踩，但这是语义静默降级。对照：`_do_assertion` 就做对了（不支持的条件显式 raise TestFailure）。一行修：condition 不在 `{active}` 支持集就 raise。

### R10-5 (P3) 杂项（不阻塞）

1. Gate 脚本 `i.severity.value == "error"` stringly 比较——R7-3 同款复发（import `Severity` 用 `is`）；
2. `Repository.from_dirs(generated_root=<overrides目录>)` 语义误用：overrides 目录被当 generated_root 传入。M1 overrides-only 下功能等价，但 M3 接 generated 时这里必须改（generated 与 override 的解析语义不同）——建议加 `# TODO(M3)` 记账；
3. Gate 的 `run_id` 固定 `"p1_m1_gate"` 且 trace.db 跨次运行累积——现在库里已有 6 轮 run 同 run_id 的 runs，按 run_id 查询会取多批。建议 run_id 带时间戳（`p1_m1_gate_20260929_1410`）；
4. `TAP_SETTLE_SECONDS` 的 1s 缓冲在 wait_for **成功路径内**无条件 sleep——非 tap 前置的 wait 也付这个税（已在代码注释和复盘文档记账 Task 2.1，可接受）；
5. `PytestCollectionWarning` ×2（`TestFailure`/`TestcaseRunner` 被误当测试类收集）——测试文件 import 触发，无害；要消可在导入处 `__test__` 标注或 conftest 过滤。
